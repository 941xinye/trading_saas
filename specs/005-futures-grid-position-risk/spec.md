## User Scenarios & Testing *(mandatory)*

### User Story 1 - 合约网格策略全周期 (Priority: P1)

交易者订阅了支持合约策略的套餐，创建一个 USDT 本位永续的合约网格实例：设置杠杆、网格区间与格数后启动。系统按价格穿越网格线自动开仓（做多侧买入开仓/做空侧卖出开仓），持仓期间按网格加仓减仓，价格到边界或用户停止时平仓结算，实现约保证金与已实现盈亏正确入账。整个周期每笔订单可按幂等单号查回，进程崩溃重启后持仓状态不丢。

**Why this priority**: 这是合约阶段的本体——四个合约策略骨架中第一个落地；没有它，仓位级风控与售卖门控都无对象可保护。

**Independent Test**: 在合约测试环境建一个合约网格实例跑完整周期（开仓→网格加减仓→平仓），验证订单回报、持仓与保证金账目、崩溃恢复三件事。

**Acceptance Scenarios**:

1. **Given** 合约网格实例处于运行中且测试环境可用，**When** 价格穿越网格线，**Then** 对应方向的开仓/平仓单被受理并成交回报入账，每笔单按幂等单号可查回且不重复。
2. **Given** 实例运行中进程被强制终止后重启，**When** 恢复逻辑执行，**Then** 持仓方向/数量/杠杆/网格进度从持久层正确重放，无重复下单。
3. **Given** 网格实例到达边界或被用户停止，**When** 触发平仓，**Then** 全部持仓平掉，已实现盈亏与保证金释放正确入账，实例进入停止态。

### User Story 2 - 仓位级风控四要素 (Priority: P1)

平台为合约仓位提供独立于账户级风控的仓位维度保护：①杠杆不超过按交易对配置的上限；②单仓名义价值与总仓位名义价值有上限；③系统持续跟踪每个仓位的预估强平价与保证金率，逼近危险区时预警并自动降风险；④所有风控动作与预警落审计可查。

**Why this priority**: 技术债 A4 的核心——现有熔断仅账户级，合约杠杆场景下一次失控仓位即可造成用户重大损失；这是平台资金安全底线，与策略本体同优先级。

**Independent Test**: 构造一个高杠杆仓位并模拟价格向不利方向移动，验证：预警在保证金率到达危险阈值前触发、自动降风险动作（减仓/平仓）执行、全程审计可查。

**Acceptance Scenarios**:

1. **Given** 用户提交杠杆超过配置上限的实例配置，**When** 创建实例，**Then** 请求被拒绝并给出明确原因。
2. **Given** 持仓的保证金率随价格移动持续恶化，**When** 到达预警阈值，**Then** 系统发出预警通知（复用现有通知链与去重冷却）；到达行动阈值，**Then** 自动执行减风险动作（先减仓，必要时市价平仓）。
3. **Given** 任一风控动作执行，**When** 查询审计，**Then** 动作类型/触发原因/动作前后仓位状态完整可查。

### User Story 3 - 熔断语义在合约语境下的延伸 (Priority: P2)

账户级熔断（只停开新仓、平仓永远放行）在合约场景保持语义一致：熔断触发期间，合约开仓与加仓被拦截，但所有减仓/平仓请求放行——绝不在用户亏损时锁死逃生通道。仓位濒临强平的紧急状态可独立触发"仅允许减仓"的保护模式。

**Why this priority**: 语义一致性问题——若熔断在合约场景误拦平仓，会把可控亏损变成穿仓；但它是 US1/US2 之上的约束规则，随本体交付。

**Independent Test**: 触发账户熔断后提交平仓单与开仓单各一笔，断言平仓放行、开仓拦截。

**Acceptance Scenarios**:

1. **Given** 实例处于熔断 OPEN 状态，**When** 提交合约平仓请求，**Then** 请求放行执行。
2. **Given** 实例处于熔断 OPEN 状态，**When** 提交合约开仓/加仓请求，**Then** 请求被拦截并记录原因。
3. **Given** 某仓位进入紧急保证金状态，**When** 新的加仓请求到达，**Then** 被拒绝且该仓位只接受减风险操作。

### User Story 4 - 售卖门控回归：卖出能力不超代码 (Priority: P2)

合约网格策略实现并通过验证后，重新进入套餐策略白名单：订阅相应套餐的租户可创建合约网格实例，未订阅的租户被拒绝。任何未实现的合约策略（其余三个骨架）仍不得出现在任何套餐白名单中。

**Why this priority**: 技术债 B1 的闭环动作——白名单摘除是上一阶段的防超卖临时措施，合约网格落地后回归白名单是交付完成的标志；但它依赖 US1 先完成。

**Independent Test**: 以 pro/free 两个套餐租户分别尝试创建合约网格实例，断言门控行为与套餐配置一致；白名单中不存在未实现策略。

**Acceptance Scenarios**:

1. **Given** 套餐白名单已加入合约网格，**When** 订阅该套餐的租户创建合约网格实例，**Then** 创建成功。
2. **Given** 租户套餐不含合约策略，**When** 创建合约网格实例，**Then** 被门控拒绝。
3. **Given** 平台任意套餐配置，**When** 检查策略白名单，**Then** 白名单中每个策略均已实现（结构性断言，防再次超卖）。

---

### User Story 5 - 合约下单纳入计费闸门 (Priority: P2)

合约下单与平仓走平台既有的两阶段计量闸门：任何合约交易所动作发生前完成权益校验与配额冻结，受理后结算、拒绝/异常冲正，与现货订单语义完全一致——合约不因新增而绕过计费。

**Why this priority**: 计费语义不可降级是平台宪法级约束（V），必须随合约下单一起交付；实现上是复用既有闸门路径，工作量小于 US1/US2。

**Independent Test**: 配额耗尽的租户提交合约开仓请求，断言被拒绝且交易所零调用；配额充足时正常下单且计量事件正确落库。

**Acceptance Scenarios**:

1. **Given** 租户当日合约下单配额已耗尽，**When** 提交合约开仓，**Then** 请求在交易所调用前被拒绝，配额计数不变。
2. **Given** 配额充足，**When** 合约开仓被交易所受理，**Then** 计量事件按既有语义结算；被拒绝或异常，**Then** 冲正还额。

---

### Edge Cases

- 价格跳空直接越过预警与行动阈值（极端行情）：自动减风险动作可能失败或不及执行，必须退化为市价紧急平仓 + 高优告警，且失败不可静默。
- 强平价预估的输入不确定性：交易所维持保证金率分档、资金费率侵蚀——预估必须保守（宁可提前预警），并注明与交易所实际强平价的偏差容忍。
- 合约数量与名义价值的精度与最小下单量约束：杠杆放大后最小名义价值约束更易触发，数量对齐必须按交易所合约规格。
- 持仓模式选择（单向 vs 双向对冲）：首期只支持单向持仓，双向模式的语义复杂度明确排除在范围外并留待后续。
- 逐仓 vs 全仓：默认逐仓（风险隔离，爆仓不殃及账户其他资金），全仓模式不在首期范围。
- 崩溃恢复与仓位快照：合约持仓状态（方向/数量/杠杆/强平价）必须纳入既有双写（Redis 每 bar + DB 快照）恢复链，且恢复幂等守卫用独立标志（constitution IV）。
- 网格挂单与仓位级风控的并发竞争：风控减仓动作与网格自身的平仓动作同时到达时，必须有单飞约束避免重复平仓。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持创建 USDT 本位永续合约网格实例，支持配置：交易对、杠杆（受上限约束）、网格区间、格数、每格数量、边界处理策略。
- **FR-002**: 系统 MUST 在实例创建与运行全程执行杠杆上限、单仓名义价值上限、总名义价值上限校验，超限请求拒绝并说明原因。
- **FR-003**: 系统 MUST 持续跟踪每个合约仓位的预估强平价与保证金率，按可配置的预警/行动两级阈值触发通知与自动减风险动作（减仓优先、紧急时市价平仓）。
- **FR-004**: 预警通知 MUST 复用现有通知渠道链与 15 分钟去重冷却；风控动作 MUST 落审计记录（动作类型/原因/前后状态）。
- **FR-005**: 合约订单 MUST 使用与现货一致的 clientOrderId 幂等模板与查询回补语义（含撤单幂等处理）。
- **FR-006**: 合约持仓状态（方向/数量/杠杆/预估强平价/网格进度）MUST 纳入既有崩溃恢复双写链（Redis 每 bar + DB 快照），恢复幂等且经 SIGKILL 注入验证（constitution IV）。
- **FR-007**: 账户级熔断在合约场景 MUST 保持「只停开新仓」语义：开仓/加仓拦截，平仓/减仓永远放行。
- **FR-008**: 仓位紧急保证金状态 MUST 独立于账户熔断生效：该状态下仅接受减风险操作。
- **FR-009**: 合约下单 MUST 走既有两阶段计量闸门（动作前校验+冻结；受理结算；拒绝/异常冲正），拒绝路径交易所零调用。
- **FR-010**: 合约网格验证通过后 MUST 回归套餐策略白名单，且平台 MUST 提供结构性断言保证白名单中不存在未实现策略。
- **FR-011**: 所有金额/数量/保证金/强平价计算 MUST 用字符串精度运算，时间统一 UTC（constitution II）。
- **FR-012**: 自动减风险动作与网格自身平仓动作 MUST 有单飞约束，同一仓位不并发执行冲突操作。

### Key Entities *(include if feature involves data)*

- **合约网格实例（Futures Grid Instance）**：在现有策略实例上扩展合约属性——杠杆、持仓模式（首期单向）、保证金模式（首期逐仓）、边界策略；沿用既有实例生命周期与熔断挂接。
- **合约仓位快照（Futures Position Snapshot）**：方向/数量/开仓均价/杠杆/预估强平价/保证金率/未实现盈亏；随既有 position_snapshot 链持久化，用于崩溃恢复与风控计算。
- **仓位风控事件（Position Risk Event）**：预警/行动两级事件——触发阈值、动作类型（预警/减仓/紧急平仓）、执行结果、前后仓位状态；落审计并可查询。
- **风控阈值配置（Risk Threshold Config）**：按交易对可配置的杠杆上限、名义价值上限、预警/行动保证金率阈值；默认值平台统一，实例可收紧不可放宽。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 合约网格在测试环境完成全周期实跑：开仓→网格加减仓→平仓结算全部成交回报入账，每笔订单按幂等单号查回一致。
- **SC-002**: 崩溃恢复验证通过：SIGKILL 强杀后重启，合约仓位与网格进度正确重放、无重复下单（对齐 P1 崩溃恢复验证法）。
- **SC-003**: 预警及时性：在模拟的不利行情下，预警在保证金率触及危险区前触发，行动阈值触发后自动减风险动作成功执行且审计完整。
- **SC-004**: 熔断语义验证：OPEN 状态下平仓请求 100% 放行、开仓请求 100% 拦截（自动化断言）。
- **SC-005**: 计费语义验证：配额耗尽路径交易所零调用；受理/拒绝/异常三条路径的计量事件与现货语义一致（既有闸门测试范式扩展）。
- **SC-006**: 门控回归验证：白名单结构性断言通过——任意套餐白名单不含未实现策略；含合约套餐租户可创建、不含的被拒。
- **SC-007**: 精度回归：全部合约金额/数量/强平价计算在边界用例（极小数量、极大杠杆、尾数舍入）下无浮点精度损失。

## Assumptions

- 首期范围：USDT 本位永续 + 单向持仓 + 逐仓模式；双向持仓、全仓模式、币本位合约明确不在本期。
- 首个落地的交易所合约能力为 Binance USDT 本位永续（现有 BinanceFuturesAdapter 仅强平流，交易接口需按既有现货适配器范式补全）；多交易所合约扩展随各自适配器阶段进行，spec 不绑定单所。
- 强平价预估为平台侧保守估算，不承诺与交易所强平引擎逐位一致；偏差方向必须是"更早预警"。
- 其余三个合约策略骨架（合约定投/马丁格尔/趋势滚动）仍不在本期，白名单结构性断言保证其不被售卖。
- 资金费率影响纳入保证金率监控的输入（按费率结算事件更新），费率套利策略不在范围。
- testnet 可达性依当前网络环境而定（坑 #23）；验证路径按宪法准备离线断言 + 真实 testnet 两条路径。
