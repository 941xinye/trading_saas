## 步骤 1：账实对账（最高优先级）

**背景**：[SpotGridStrategy](../app/Domain/Strategy/Spot/SpotGridStrategy.php) 的持仓是内存态（grids/position_qty），仅靠 Redis+DB 快照做崩溃恢复，**从不与交易所真实余额核对**，长期漂移（漏成交、手工转出、异常回滚）不可发现；类注释中"真实持仓以 exchange getBalance 对账为准"的 TODO 即此项。同时崩溃恢复后 pending 格永久阻塞，未用 `getOrder` 核实交易所侧真实结果。`max_drawdown` 也缺真实净值口径（A3）。

**目标**：定时比对"策略账本 vs 交易所账户"，差异分级落库，严重差异自动暂停实例并告警。

**范围**

- 做：
  1. 新增 `app/Domain/Reconciliation/`：`ReconciliationService`（比对 + 分级 + 落库）、容差策略（配置驱动）。
  2. 新表 `reconciliation_reports`：tenant_id / strategy_instance_id / exchange_account_id / status(`ok|drift|critical|unknown`) / diff_json / checked_at；唯一键 `(tenant_id, strategy_instance_id, period_key)` 保证同周期幂等；复合索引 `(tenant_id, strategy_instance_id, checked_at)`。
  3. 命令 `reconcile:run {--instance=} {--period=5m}` 与 `reconcile:status {instance}`；对账走独立命令/队列，**绝不进行情协程进程**（坑 #1：REST 是阻塞 curl）。
  4. 比对维度（现货）：base 资产数量（交易所 free+locked vs 策略汇总持仓）、策略累计买入成本与 strategy_orders 成交汇总、balance_snapshots 净值序列（为 A3 的真实 drawdown 提供数据口径，本步只产数据不改风控算法）。
  5. 差异分级：容差内（默认数量 1e-6 或等值 5 USDT，config 可调）→ `ok`；容差外 → `drift`；超严重阈值（如等值 50 USDT 或方向为"账本有、交易所无"）→ `critical`。
  6. `critical`：实例转暂停态（复用 paused 语义，新增区分值 `paused_by_reconcile`），通知走 P4 已验证的通知链落库审计。
  7. 崩溃恢复增强：hydrate 后对 pending 格携带的 clientOrderId 调 `getOrder()` 核实——`filled` → 走 onFill 入账；`canceled/rejected/查无此单` → 释放 pending 格。
- 不做：自动改账/自动补单/自动平仓（全部人工处理）；合约持仓对账（合约策略未实装，等合约策略落地时同模式扩展）；不修改 max_drawdown 算法本身。

**实现要点**

- adapter 契约已有 `getBalance(): ExchangeBalance` 与 `getPosition()`，无需改接口；BinanceSpot 的 getBalance 已在 P1 联调中用过。
- 对账调用放 queue job（notifications/default worker）或独立 cron 命令，禁止放入 market:feed 协程。
- `getBalance` 网络异常 → 本次结论 `unknown`，**不暂停、不告警 critical**（防止网络抖动误杀）；连续 N 次 unknown 才告警（建议 N=3）。
- 复用 P3 计量审计风格：报告不可变、只追加；period_key 用 UTC 周期桶。
- 暂停态必须与 RiskGuard 熔断态正交存储，互不覆盖。

**验收标准（`poc:verify-reconcile`，建议 ≥12 项断言）**

1. 账实完全一致 → `ok`，diff_json 各维度差值为 0。
2. 注入策略侧少币（账本 < 交易所）→ `drift`，实例不暂停。
3. 注入交易所侧少币（账本 > 交易所）→ `critical`，实例被暂停且通知审计落库。
4. dust 差异（容差内）→ 仍 `ok`。
5. `getBalance` 抛异常 → `unknown`，实例不暂停；连续 3 次 unknown 才产生告警。
6. 同 period_key 重跑 → 幂等，不产生第二条报告。
7. 多租户并行：A 租户漂移不出现在 B 租户报告（TenantScope 断言）。
8. critical 后 `reconcile:status` 输出差异明细与暂停原因；熔断态实例不被对账暂停覆盖。
9. 恢复场景 A：pending 单 `getOrder=filled` → 数量/成本正确入账，pending 清除。
10. 恢复场景 B：pending 单 `getOrder=canceled` / 查无 → pending 格释放，下一根 bar 可重新触发。
11. 恢复场景 C：getOrder 网络异常 → pending 保持阻塞（保守，不放行），状态记 unknown。
12. 全程 bcmath；构造的极端小数差不产生浮点误判。
13. testnet 实跑：真实小额成交后对账 `ok`；手工从 testnet 账户转出小额资产能在下一周期检出 drift。

**风险**：testnet 资产可被手工/其他实例共用，实跑需专用账户；容差阈值过紧会噪声告警，先按 5/50 USDT 默认值灰度。

## 步骤 2：SpotDca 策略落地

**背景**：[SpotDcaStrategy](../app/Domain/Strategy/Spot/SpotDcaStrategy.php) 五个方法全部 `throw Not implemented`，但 [config/plans.php](../config/plans.php) 的 free 套餐已向用户承诺 `spot_dca`——配额门会放行一个必定崩溃的实例（A2）。StrategyRegistry 中 `spot_dca` 映射已存在，补实现即可售卖闭环。

**目标**：按固定周期定额买入，累计笔数达上限后停止；崩溃可恢复。

**范围**

- 做：
  1. 实现 onBar 驱动的时间判断（以 **bar.closeTime（UTC）** 为准，不用本机时间）：距 `last_order_at` ≥ `interval_minutes` 且 `orders_count < max_orders` → 产生一个市价 buy 信号，数量 = `amount_per_order / close`（8 位小数截断，复用网格的 bcmath 算法）。
  2. params（写入 config/strategy.php 默认值）：`interval_minutes`（默认 10080=周定投；POC 传 1–2）、`amount_per_order`（USDT）、`max_orders`。
  3. onFill：成交 → orders_count+1、total_spent 累加、last_order_at 落快照；失败/拒绝 → 不计次数、冷却不推进（下一周期可重试）。
  4. 快照结构 `{orders_count, total_spent, last_order_at}`，走与 SpotGrid 相同的 Redis 每 bar + DB 60s 双写；**独立 `$hydrated` 一次性标志且 hydrate 先于业务判断**（坑 #9）。
  5. 信号经现有 Runner → QuotaGuard（orders 日配额）→ OrderExecutor（clientOrderId 幂等），无新链路。
- 不做：定投的卖出/再平衡（本期只买）；价格条件单（跌得多买得多）；合约 DCA。

**明确语义（防争议）**：断连期间漏掉的周期**不补单、不顺延累计**——恢复后以实际到达的 bar 重新计时。理由：避免长断连恢复后突发连买；该语义写入策略注释与 README。

**验收标准（`poc:verify-spot-dca`，≥9 项）**

1. 首根 bar / 未到 interval → 无信号。
2. interval 到期 → 恰好 1 个 buy 信号，qty = amount/price（8 位截断），与网格算法一致。
3. 随后未到期的多根 bar → 无信号（不重复买）。
4. orders_count 达到 max_orders → 永不再产生信号。
5. onFill(filled) 后 count/total_spent/last_order_at 正确更新；onFill(失败) 三项不变。
6. kill -9 重启：计数与 last_order_at 从快照恢复，冷却窗口不重置（坑 #9 场景复演）。
7. amount 过小导致 qty 截断为 0 → 不下单、不计次、记 warning（与 OrderExecutor 数量归零冲正路径一致）。
8. Registry::make('spot_dca') 返回实例；free 套餐租户可建实例过 PlanService 白名单；下单受 orders_per_day 配额拦截验证。
9. WSL testnet 实跑：interval=1min、amount=5 USDT 跑 2–3 笔真实成交，strategy_orders / meter_events 落库正确，崩溃恢复后续跑不重复投。
